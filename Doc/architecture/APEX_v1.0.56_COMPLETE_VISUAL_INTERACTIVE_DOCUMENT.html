Boundary rules

How to read the system

Runtime layer IDs (L*) describe responsibility and call direction. File-zone IDs (F*) describe where code lives. A file zone can support more than one runtime layer.
Historical live-boot notes are kept as historical evidence only. This current snapshot includes a fresh production build in `dist/` and regenerated release artifacts.
Truth rule: provider failure must become LIVE / DEGRADED / UNAVAILABLE / NOT_CONFIGURED with provenance—never a made-up fallback value.

Current implementation

What exists today

Provider hierarchy for market data IMPLEMENTED

Binance public → KuCoin public → owner-managed HF Space-4 / Space-2 → operator-entered CoinMarketCap as the final quote fallback.

Supplemental intelligence hierarchy IMPLEMENTED

HF Spaces first; user-entered Newsdata.io / Hugging Face inference / Etherscan / TronScan / BSC explorer credentials are later tiers.

Smart Autopilot on both pages IMPLEMENTED

src/App.tsx passes the same persisted autopilotEnabled state and setter to BacktestingPage and StrategyPage; both pages call /api/strategies/autopilot/cycle.

Five-agent optimizer promotion gate IMPLEMENTED

Smart Autopilot uses EVIDENCE, HOLDOUT, COST_STRESS, STABILITY and OVERFIT_GUARD assessments before automatic promotion.

Multi-strategy paper council IMPLEMENTED

Autopilot replays successful contexts through multi-strategy research and a paper-only multi-agent portfolio council.

Liquidity Hunter safety boundary IMPLEMENTED

Shadow-only, non-authoritative, manual/paper execution policy with an explicit decision bridge before execution.

No fabricated fallback values IMPLEMENTED

Provider and pricing code returns unavailable/not-configured states instead of inventing missing market values.

Manual Liquidity Hunter testnet confirmation UI IMPLEMENTED

StrategyEvidenceRail.tsx contains the explicit confirmation dialog and real submit action; this older gap is closed.

Componentized Backtesting evidence UI IMPLEMENTED

BacktestingPage composes RunBuilder, EvidenceHero, EvidenceTabs, metric/runtime panels and presets; it is no longer a raw JSON result view. The regression fixture matches current preset props.

Required next architecture

These boxes are NOT implemented yet

Everything in this section is a future requirement / remediation item. It must not be read as current APEX behavior.

1. Persistent server-side Smart Autopilot scheduler NOT IMPLEMENTED

Current endpoint reports scheduler.mode = CLIENT_OPT_IN and serverBackgroundLoop = false. The 5-minute loop is page/session driven. Implement a durable, bounded server-side scheduler if Autopilot must continue when the browser workspace is closed.

2. Synchronized multi-symbol universe identity NOT IMPLEMENTED

apexNextMarketRoutes.ts explicitly blocks automatic promotion for portfolio-style optimization until synchronized universe identities are persisted.

3. Single provider-policy registry NOT IMPLEMENTED

The approved hierarchy is implemented but spread across marketDataService.ts, intelligenceFeedProbe.ts, supplementalOrchestrator.ts, usdPricing.ts, hfSpaceIntel.ts and hfSpacesClient.ts. A single typed policy registry should own domain × provider priority, capability and failure semantics.

4. Private runtime configuration directory NOT IMPLEMENTED

Supplemental, external-source and Telegram secrets are still persisted under process.cwd() as .supplemental.config.json, .external-api-sources.config.json and .telegram.config.json. Move them to a dedicated private user-data/runtime directory.

5. Complete OpenAPI coverage NOT IMPLEMENTED

Current source exposes 135 statically registered HTTP operations and openapi/apex-api.v1.yaml documents all 135 (100.0%). The drift gate enforces this contract.

6. Route/composition decomposition NOT IMPLEMENTED

server.ts is 3,784 lines and apexNextMarketRoutes.ts is 2,350 lines. Split by bounded domains while preserving middleware ordering and route contracts.

7. Fresh production build + boot + load verification NOT IMPLEMENTED

Fresh `npm run build` output exists for this exact tree. Browser/visual and long HTTP/WebSocket soak remain separate verification items where Playwright/runtime infrastructure is available.

8. Architecture drift automation NOT IMPLEMENTED

Generate the file-layer map, route inventory, provider hierarchy and implementation-status matrix from source metadata during CI so the visual document cannot silently drift from code.

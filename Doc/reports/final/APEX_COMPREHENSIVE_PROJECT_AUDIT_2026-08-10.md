## 2. Executive assessment

The project is a substantial **React 19 + Vite frontend with an Express/TypeScript backend**, with mature strategy research/backtesting services, a bounded Smart Autopilot optimizer, a five-role multi-agent research council, Liquidity Hunter research surfaces, manual/testnet execution controls, extensive source-contract QA, and a sizable evidence/documentation corpus.

The strongest positive finding is that the **research/paper safety boundary is explicit and currently verified**: the Multi-Agent/Multi-Trading runtime creates paper sizing intents rather than executable exchange orders, binds plans by fingerprint, rejects tampering, retains manual confirmation, keeps autonomous live execution disabled, and does not allow the risk governor to be bypassed.

The most important deficiency is **release hygiene around local secrets/config state**. Three runtime configuration files were present in the source delivery despite explicit repository rules forbidding them; the built-in release gate failed on those files. They have been removed from this audited delivery copy, with only non-secret metadata preserved as evidence, and the source-only release secret gate now passes. The durable application-level fix is still pending because `server.ts` persists those settings to root paths.

## 4. System architecture

### 4.1 Frontend shell and routing

- `src/main.tsx` initializes global styling/theme, service-worker registration in production and the top-level route error boundary.
- `src/App.tsx` is the central workspace state/router coordinator.
- `src/components/workspace/WorkspaceShell.tsx` owns the global APEX shell.
- The active workspace exposes Overview, Markets, Watchlist, Portfolio, Trading, Orders, Positions, Alerts, History, Analytics, Backtesting, Strategies, Settings and Help.
- Trading, Backtesting and Strategy Studio are lazy-loaded rather than bundled into the initial page coordinator.

The detailed frontend dependency/index findings are recorded in `PROJECT_STRUCTURE_2026-08-10.md`.

### 4.2 Backend and API

`server.ts` composes Express/Vite, request identity/drain handling, CORS allow-listing, mutation authorization/CSRF/operator-token checks, rate limiting, account/execution endpoints, provider integrations, operations/health, local configuration persistence and supporting services.

`src/services/apexNextMarketRoutes.ts` is the main market/strategy/backtesting router. It contains strategy registry surfaces, validation/fusion, canonical backtesting, robust optimization, Smart Autopilot, multi-strategy research and paper sizing endpoints.

The runtime API map contains **128 operations**. OpenAPI currently covers **27 operations (21.1%)**. Importantly, all 27 documented operations correspond to runtime routes after `:id` / `{id}` normalization; the gap is primarily missing documentation, not a detected contract contradiction.

### 4.3 Strategies and Backtesting

`src/services/strategyRegistry.ts` contains **14 definitions**: 10 candidate/Core strategies and four intentionally blocked research strategies. Backtesting uses real replay/strategy-specific execution paths and the source QA explicitly rejects fabricated performance or insufficient-data success states.

The robust optimizer uses chronological evaluation, untouched holdout, successive halving, cost stress, neighbor stability, overfit/drawdown/sample gates, bounded search and exact-context promotion. User parameters remain higher priority than promoted defaults.

### 4.4 Smart Autopilot

The Smart Autopilot pipeline rotates bounded Strategy × Market × Timeframe × Direction contexts. A Challenger must pass a five-agent optimization council:

- `EVIDENCE`
- `HOLDOUT`
- `COST_STRESS`
- `STABILITY`
- `OVERFIT_GUARD`

Source QA also confirms recurrent optimization begins from the active promoted profile rather than resetting improvements each cycle, while legacy direct optimizer auto-promotion remains disabled.

### 4.5 Multi-Agent / Multi-Trading

The research council uses five deterministic roles:

- `PERFORMANCE`
- `RISK`
- `CONFLICT`
- `PORTFOLIO`
- `EXECUTION_GUARDIAN`

The orchestrator is bounded by concurrency/time constraints and preserves conflicts as evidence. Paper portfolio admission fails closed for negative or undersized evidence. The paper sizer creates **non-executable sizing intents**, with no exchange dependency, and server receipts bind the exact plan set by fingerprint.

### 4.6 Persistence and operational state

The frontend persists selected UX/workflow state in browser storage. Server-side services use local/private JSON and event-log files for decision memory, adaptive/edge threshold governance, optimization revisions, testnet/paper-canary state and related operational evidence.

The current local credential/config persistence locations in `server.ts` are a release-hygiene problem because they resolve to the repository root. See `SEC-01`.

### SEC-01 — Local secret-bearing runtime configuration was present in the source delivery

**Severity:** HIGH

**Evidence:** Baseline contained `.telegram.config.json`, `.supplemental.config.json`, and `.external-api-sources.config.json`. The repository contract says these must never be committed; the project release gate failed on exactly these paths. The audited delivery removes the files and the source-only secret gate then passes.

**Recommendation:** Move persisted local credentials/configuration out of repository root to a private user-data/runtime directory (for example `.apex-data/secrets/` outside release packaging, preferably with an environment override). Keep only non-secret example templates in source.

### IDX-01 — Function atlas was stale relative to the audited source tree *(resolved in current snapshot)*

**Severity:** HIGH

**Evidence:** The function index was generated at 2026-08-09T16:22:05.544Z; hash comparison found 23 indexed code files changed and 9 new code files absent from the atlas.

**Recommendation:** Regenerate `Doc/FUNCTION_INDEX.md/json` with `npm run index:functions` on a dependency-complete machine after each accepted code change; add a CI freshness gate if possible.

### DOC-01 — Agent navigation reference contains materially stale current-state and line anchors

**Severity:** HIGH

**Evidence:** `Doc/architecture/Refrence.md` still presents a 2026-07-27 current state with 226/226 tests and line ranges for a multi-thousand-line `src/App.tsx`; current `App.tsx` is much smaller and the current test inventory is 313 tests in 82 files.

**Recommendation:** Treat old entries as historical, keep the new 2026-08-10 audit refresh at the top, and progressively replace brittle numeric line maps with stable search anchors/component paths.

### API-01 — OpenAPI contract covers only a minority of runtime operations

**Severity:** MEDIUM

**Evidence:** Static discovery found 128 unique API operations; OpenAPI documents 27 (21.1%). The documented operations do match runtime routes, so this is primarily a completeness gap.

**Recommendation:** Expand OpenAPI incrementally by endpoint family, prioritizing account/execution, provider, operations and persistence-changing APIs. Add an operation-coverage report to CI.

### ARCH-01 — Server and route composition are concentrated in very large modules

**Severity:** MEDIUM

**Evidence:** `server.ts` is 3,785 LOC and `src/services/apexNextMarketRoutes.ts` is 2,350 LOC, combining multiple operational domains.

**Recommendation:** Extract routers by domain behind the same external API contracts: account/execution, providers, operations, strategy/backtest/autopilot. Keep shared authorization/rate-limit middleware centralized.

### CSS-01 — CSS cascade is very large and layered

**Severity:** MEDIUM

**Evidence:** `src/index.css` is 7,422 LOC; `reference-ui.css`, Backtesting CSS and light-theme refinement each exceed 3,700 LOC.

**Recommendation:** Move new page-specific rules into scoped page styles; retire superseded selectors after visual regression proof; add selector/dead-rule analysis rather than layering more overrides.

### DOC-02 — Documentation distribution policy no longer matches the package

**Severity:** MEDIUM

**Evidence:** `Doc/README.md` says generated indexes, archived plans and QA are intentionally not distributed, while the delivered package contains those categories.

**Recommendation:** Decide whether this is a lightweight source package or a full evidence package and update `Doc/README.md`/release packaging rules accordingly. This audit updates the README to describe the current full-evidence delivery.

### ROOT-01 — Root contract does not list several legitimate current root directories/files

**Severity:** MEDIUM

**Evidence:** The strict allow-list omits `.github/`, `.claude/`, `.nvmrc`, `.node-version`, `openapi/`, `tools/`, `vendor/`, `_archive/`, and QA evidence locations even though several are deliberate project assets.

**Recommendation:** Reconcile `ROOT_CONTRACT.md`: distinguish tracked project roots, ignored runtime/QA roots, and forbidden secret state. Do not solve the mismatch by broad wildcards.

### GRAPH-01 — A few source dependency cycles remain, mainly through type imports

**Severity:** LOW

**Evidence:** Static production-module analysis covered 304 production modules / 894 internal edges and found three SCCs larger than one module: the scanner/type cluster (`mathEngine`, `scannerConfigPolicy`, `scannerCore`, `smartMoneyContextEngine`, `types`), `accountClient` ↔ `workspaceInsights`, and `newsApiRequest` ↔ `supplementalTypes`. Inspection shows the back-edges are type imports or type-position imports, so no runtime-recursion defect was demonstrated.

**Recommendation:** Where practical, move shared interfaces into contract/type-only modules to make directionality explicit. Prioritize only if bundler/test evidence shows real impact.

### ENV-01 — Fresh install/build/unit-suite could not be reproduced in this sandbox

**Severity:** ENV

**Evidence:** No `node_modules` is shipped. The accepted install log shows the internal package mirror returning 404 for the locked Vitest artifact; therefore a fresh Vite build/typecheck/Vitest run was not claimed here.

**Recommendation:** Run `npm ci && npm run verify` in CI or a machine with a complete registry mirror. Preserve the lockfile and attach the resulting build/test provenance to the release.

### PKG-01 — The evidence-rich delivery is large and contains historical QA/archive material

**Severity:** INFO

**Evidence:** The source snapshot includes `QA/`, `_qa/`, `_archive/`, historical screenshots and generated indexes. These are useful for auditability but inflate distribution and duplicate some active-source bytes.

**Recommendation:** Produce two artifacts: reproducible source release (no ignored QA/local state) and separate evidence/archive bundle. Keep checksums linking the two.

## 10. Security and release hygiene

The baseline source delivery contained three ignored local configuration files. Their **contents are intentionally omitted** from this report. Metadata-only evidence (path, byte size, SHA-256) is retained under `_qa/comprehensive-audit-2026-08-10/security-baseline/`.

The audited delivery removes these local files and reruns `scripts/gates/checkNoSecretsInRelease.mjs --source-only`, which passes. No source-default secret values were inferred from `src/config/completedApiDefaults.ts`; its secret fields are empty/defaulted. A conservative token-pattern scan of 774 active text files did not find additional OpenAI/GitHub/AWS/private-key/Telegram/Hugging-Face token patterns after remediation.

**Remaining design deficiency:** `server.ts` still resolves the supplemental, external-source and Telegram configuration stores against `process.cwd()` at repository root. If operators save these settings, root can become dirty again and the release gate can fail. Move these paths out of release source.

## 11. What was not proven

This audit does **not** claim a fresh install, TypeScript compilation, Vite production build, full Vitest suite, or fresh browser/pixel QA. The delivered source package also contains no `.git/` metadata, so branch/commit ancestry and tracked-vs-untracked status cannot be independently reconstructed from this artifact alone. The source package does not contain `node_modules`, and the available accepted install log shows the environment's internal npm mirror returning HTTP 404 for the locked Vitest artifact. This is an environment/reproducibility limitation for this run, not evidence that the code fails to build.

Required release follow-up on a dependency-complete machine:

```bash
npm ci
npm run verify
npm run build
npm run index:functions
npm run index:docs
npm run docs:check
npm run release:gate:source
```

For UI releases, also rerun the project's required 1368×753 browser/visual acceptance path and attach screenshots/runtime evidence.

## 13. Final audit position

The repository contains a broad and unusually well-instrumented research/backtesting stack. The **Smart Autopilot and Multi-Agent/Multi-Trading paths are demonstrably bounded to research/paper behavior in the verifiers executed here**, and the recent Strategy Studio/Backtesting feature-preservation contracts pass.

The project should nevertheless **not be treated as fully release-clean until the local-secret persistence path is redesigned and the fresh dependency/build pipeline is reproduced**. The audited delivery is safer than the input package because the forbidden local config files have been removed and the source secret gate now passes.

Future agents should start from the structure, file and API indexes generated by this audit, then consult the refreshed `Refrence.md`. Any new architectural change should update these navigation artifacts or regenerate them as part of acceptance.

# Windows offline dependency restore

This project is Windows-compatible and targets Node.js 22.x through 24.x with npm 10.9+.

When an `apex-npm-tarballs.zip` bundle is available, place it in the project root and run:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\windows\Restore-OfflineDependencies.ps1 -TarballZip .\apex-npm-tarballs.zip
```

The script extracts tarballs to `.offline-deps`, seeds `.npm-cache`, runs `npm ci --prefer-offline`, and then executes the canonical checks.

The uploaded bundle used for v1.0.63 had one missing optional Windows Rollup tarball reported in `downloads-manifest.txt`:

```text
https://registry.npmjs.org/@rollup/rollup-win32-x64-msvc/-/rollup-win32-x64-msvc-4.62.4.tgz
```

If the machine has internet access, npm will fetch that optional dependency during `npm ci --prefer-offline`. If the machine is fully offline, add that exact `.tgz` to the bundle before running the restore script.

Synthetic smart backtesting fixtures are generated by:

```powershell
node .\scripts\qa\generateSmartBacktestingSyntheticFixtures.mjs
node .\scripts\qa\verifySmartBacktestingRuntimeHardening.mjs
```

They are explicitly labeled: `Synthetic fixture data for offline verification only. Not live market data.`
